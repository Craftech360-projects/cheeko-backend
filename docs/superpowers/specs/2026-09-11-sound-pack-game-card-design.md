# Sound-Pack Game Card — Backend Design

Written 2026-09-11. Implements the backend and dashboard half of
`sound-pack-game-plan.md` §10 (B1–B5), with two additions decided in review:
a `game` card type with dashboard support, and per-round data (Sound, Prompt,
File) stored in the database and sent on every scan.

## 1. What this builds

A physical RFID card, when tapped, makes the toy download a sound-quiz pack
("Around the House") and launch it. The backend stores the pack as rows,
generates the device manifest, serves every asset from the CDN, and tells the
gateway to publish a `card_game` message. Admins author packs and map cards
from the existing RFID dashboard.

## 2. Firmware state (the premise)

`D:\cheeko-os-v2` plays a `sound_quiz` pack from the SD card (Phase 1) only on
branch `origin/integration/settings-onboarding-soundpack`. No branch has a
`card_game` handler or a pack downloader; the older `card_app` branch is never
routed. **The message below is the contract the firmware builds to.** The
firmware sends no local version for app cards, so the device gates re-downloads
locally; the server always answers with the full message.

## 3. The contract

Published by both gateway senders to `devices/p2p/<clientId>`:

```json
{ "type": "card_game", "rfid_uid": "04A1B2C3",
  "app_id": "hometown", "name": "Around the House", "version": 3, "content_hash": "sha256...",
  "prompts": [
    { "sound": "Doorbell",        "prompt": "DING-DONG?", "file": "doorbell.mp3" },
    { "sound": "Pressure cooker", "prompt": "WHISTLE?",   "file": "cooker.mp3" }
  ],
  "assets": [
    { "name": "manifest.jsn", "url": "https://cdn/rfidcontent/apps/hometown/manifest.jsn" },
    { "name": "doorbell.mp3", "url": "https://cdn/rfidcontent/apps/hometown/doorbell-9f8e.mp3" },
    { "name": "doorbell.png", "url": "https://cdn/rfidcontent/apps/hometown/doorbell-5e4d.png" }
  ] }
```

Rules:

- `app_id` is the pack code: 1–8 chars of `[a-z0-9_-]`. It becomes the SD
  folder, which must be an 8.3 short name.
- Every `assets[].name` is 8.3. The device writes by `name`, never by URL.
- `manifest.jsn` is the file the firmware parser on the integration branch
  reads, generated by the backend at save time and hosted on S3 at a fixed key
  with `Cache-Control: no-cache`.
- `prompts` is the flat Sound | Prompt | File list, one entry per round.
- The in-session sender adds `session_id`. Nothing else differs between the
  two senders.

## 4. Data model — no migration

`rfid_content_pack`: `content_type = 'sound_quiz'`, `pack_code` = app id.

`content_item`, one row per round:

| Column | Holds | Dashboard label |
|---|---|---|
| `title` | Sound name, e.g. `Doorbell` | Sound |
| `lyrics_text` | Prompt, e.g. `DING-DONG?` | Prompt |
| `audio_url` | Sound file URL (MP3) | File |
| `image_url` | Icon URL (48×48 PNG, **not** converted to .bin) | Icon |
| `description` | Two distractor Sound names, `Kettle,Fan` | Wrong answers |
| `item_number` | Round order | position |

`contentItemsHash` already covers all five columns, so any edit changes
`content_hash` and bumps `version` through the existing save path.

`rfid_card_mapping.card_type = 'game'` with `content_pack_id` set.

## 5. Manifest and file names

`src/services/soundQuiz.js` (pure, no I/O):

- `isValidAppId(code)` — `/^[a-z0-9_-]{1,8}$/`.
- `assetStem(title)` — lowercase, strip non-alphanumerics, first 8 chars.
  Collisions get the last char replaced by a digit. `Microwave` → `microwav`.
- `buildSoundQuizPack(pack, items, manifestUrl)` → `{ manifest, assets, prompts, warnings }`.
  - Rounds ordered by `item_number`. Label = `title` uppercased.
  - A round is **dropped with a warning** when it lacks prompt, audio URL,
    icon URL, or either distractor cannot be resolved to another round's
    label. This mirrors the firmware's own drop rules.
  - `correct = keptIndex % 3`; the correct option sits at that index, the two
    distractors fill the rest in stored order.
  - Manifest: `{ type:'miniapp', template:'sound_quiz', app_id, name, color:'#4EA8DE', version, rounds }`.
  - `assets`: manifest first, then `<stem>.mp3` and `<stem>.png` per kept round.
  - `prompts`: `{ sound: title, prompt, file: '<stem>.mp3' }` per kept round.
- `manifestKeyFor(code)` = `rfidcontent/apps/<code>/manifest.jsn`;
  `manifestUrlFor(code)` = `https://<CLOUDFRONT_DOMAIN>/<key>`.

`upload.service.uploadGamePackManifest(packCode, manifest)` puts the JSON at
that key with `no-cache` and requests a CloudFront invalidation, the same
pattern as custom-card overwrites.

`rfid.service.publishSoundQuizManifest(packId)` runs at the end of
`createContentPack` and `updateContentPack`. It reads the pack, returns early
unless `content_type === 'sound_quiz'`, builds, uploads. A failure throws a
500 after the rows are committed, so the admin sees "saved, manifest failed,
save again" rather than a silently stale device.

## 6. Lookup

`buildContentPackResponse` gets a `sound_quiz` branch before the stories/flat
split. It returns (camelCase, API shape):

```
{ rfid_uid, contentType:'sound_quiz', appId, title, version, contentHash, prompts, assets }
```

No `items`, no `encryption`. An invalid app id logs a warning and returns
`null`, so the gateway answers `card_unknown`. Both the mapping path and the
custom-card path already go through this function.

## 7. Card type `game`

- `determineTapCardType`: `game` when `card_type === 'game'` or the linked
  pack is `sound_quiz`. The include in `recordCardTap` selects `content_type`.
- The lookup-fallback classifier (extracted as `classifyLookupCardType`)
  returns `game` for `contentType === 'sound_quiz'`.
- The content version handshake stays keyed on `content`, so a game card
  never receives `card_up_to_date`. Tap logs record `card_type = 'game'`.

## 8. Upload route

`POST /admin/rfid/content-pack/upload` gains `purpose=game_asset`: the file is
stored as-is (no LVGL conversion) and never sealed (`apps/` stays plaintext,
plan §9). The dashboard sends it for every sound-quiz item upload with
`category=apps/<packCode>`.

## 9. Gateway

New module `main/mqtt-gateway/gateway/card-game.js` exports `isCardGame(data)`
and `buildCardGameMessage(rfidUid, data, extra)`. Both senders use it:

- `fetchRfidContentFromManagerApi` whitelist adds `appId`, `contentHash`,
  `prompts`, `assets`.
- `mqtt-gateway.js` no-session router: the `card_game` branch runs right after
  the `card_unknown` return and **before** the `textToSend` guard, which would
  otherwise return early because a game response has no items or prompt text.
- `virtual-connection.js` in-session sender: an explicit branch before the
  `isAiCard` classification, instead of the wholesale spread.

Tests pin both call sites and the whitelist against source text, in the house
style of `card-content-encryption.test.js`.

## 10. Dashboard (manager-web)

- `contentTypes.js`: `sound_quiz` added to defaults with label "Sound Quiz (Game)".
- `RfidContentPackDialog.vue`: when the type is `sound_quiz`, item rows show
  Sound, Prompt, File, Icon and two "Wrong answer" selects fed from the other
  rows' Sound names (saved to `description` as `A,B`). Uploads send
  `purpose=game_asset`. Pack code is validated against the 8-char rule.
  Submit requires 2–16 complete rounds.
- `RfidCardDialog.vue`: fourth tile "Game Card" → `actionType='game'`,
  `cardType='game'`, content-pack select filtered to `sound_quiz` packs.
- `RfidManagement.vue`: reverse map `cardType==='game'` on edit; Cards tab
  shows a "Game" tag; tap analytics colours `game`.
- `getContentPackByCode` returns `description` per item so distractors round-trip.

## 11. Authoring script

`scripts/install-sound-pack.js <folder> [--uid <UID>] [--apply]`. Dry-run by
default. Reads a Phase 1 pack folder with its `manifest.jsn`, derives one round
per manifest round (Sound = correct label, Prompt, distractors = the other
labels, File and Icon = the correct option's files), uploads through the
raw-mode route, creates or updates the pack through the API so hash and
version logic runs, and maps the card as `game`. Auth is `X-Service-Key`,
like the MCP.

## 12. MCP impact

`upload_pack_file` gains an optional `purpose` passthrough (`game_asset`).
Envelope, auth middleware, `NO_WRITE`, and the item shape are unchanged.
`npm run test:mcp` must pass.

## 13. Out of scope

- Series (UID-range) dialog support for `game`. Add when a range is issued.
- Icon dimension validation. Add if a wrong-size icon ever ships.
- Staged/atomic update, encryption of `apps/`, `card_app` fallback.
- Firmware F1–F5. Handed off with this contract.

## 14. Verification

- Unit: builder, lookup branch, classifiers, upload route, manifest publish,

- Manual: dry-run the script on the firmware repo's `hometown` folder (16
  rounds, 32 files, 0 errors); `--apply` on the dev box; tap a mapped card
